# 一、开工前置：S4 遗留（2 项）

## 1.1 布局回到 v1.3

S4 的「组块严格不可跨列」实测 **300 逻辑 px**，且两列各空 4 行——我看了 `04-long-list.png`：第 2 列顶满 8 行，第 1、3 列只有 4 行就断，形状像没做完。

v1.2 那条规则的问题不在"要不要分组"，而在**把整组的不可分割性推到了极端**。

**v1.3 规则**：

```
组块默认可跨列；
跨列时续列顶部必须是「组名（续）」，不得出现无组名的续列；
装填按「当前最短列优先」，而不是"填满第 1 列再换列"。
```

- 「编辑」8 格会拆成 5 + 3，续列带「编辑（续）」
- 最短列优先让「导航 4 + 查找 2」凑进同一列，避免两列半空

**高度门槛同步改为 `min(320, 屏高 × 30%)`。**
S3.5 那个 260 是我拍脑袋写的，只是"12 条 4 行"的推算，没有产品依据。用屏高比例才有意义。

验收：VS Code 长列表 **≤ 320 逻辑 px，且三列高度差 ≤ 2 行**。

## 1.2 删除 D5 开关

S4 真机证明：任何铺满屏幕的窗口都让 `QUNS=2`，D1 先命中，`TreatBorderlessFullscreenAsGame` 在本机永远验证不出效果。

**决策：删开关，保留 D5 规则。**

- `GameRules.TreatBorderlessFullscreenAsGame` 字段删除，D5 恒开
- 理由：暴露一个"按了没反应"的开关比没有开关更糟；但 D5 在其他显示器/系统组合下仍可能独立生效，规则不能删
- `Case14` 改为纯函数断言：`ExclusiveFullscreen=false, Covers=true, HasCaption=false` → 必须抑制

规格 §2.2 已更新到 v1.3，照它改。

# 二、S5 范围

## 2.1 配置文件

路径：`%APPDATA%\HotkeyHud\config.json`，首次运行自动生成。

**只暴露 4 个字段**：

| 字段 | 默认 | 范围 | 说明 |
|---|---|---|---|
| `dwellMs` | 300 | 80–5000 | 长按阈值，用户真的会想调 |
| `knownShortcuts` | `null` | — | `null`=内置默认；`[]`=关闭过滤；数组=完全替换 |
| `extraGameProcesses` | `[]` | — | 游戏名单兜底 |
| `startWithWindows` | `false` | — | 与注册表状态保持同步 |

**不暴露**：`flashMs`、`maxVisibleItems`、面板宽度/列数/配色。这些由 §6.1 定死，开放出去只会让用户调坏。

配置损坏（JSON 语法错、字段类型错）→ **用默认值启动，不崩**，托盘气泡提示一次，并把原文件改名为 `config.broken.json` 保留证据。

## 2.2 托盘

| 菜单项 | 行为 |
|---|---|
| 状态（禁用项） | 显示「正常 · 前台 X」或「已抑制（原因）」 |
| 暂停 / 恢复 | 切换 G1，接进 `Suppressed` 并集 |
| 重载数据 | `ShortcutRepository.Reload()` + 重建 `KnownShortcutFilter` |
| 打开配置目录 | 资源管理器 |
| 开机自启（勾选） | 写 / 删 HKCU Run |
| 退出 | 释放 Raw Input、隐藏托盘、退出 |

图标：**代码绘制的 16×16**，用 Ctrl 强调色 `#4C8DFF` 做底 + 白色键帽形。不要用 `SystemIcons.Application`——和几百个程序长得一样。

## 2.3 抑制并集（S5 的关键点）

```
Suppressed = 手动暂停 || 游戏/全屏抑制
```

**两个来源独立**：暂停时切到游戏再切回来，暂停状态不能被游戏抑制"覆盖掉"；反之亦然。
S4 已实现并集，S5 接托盘开关时**必须走同一个变量**，不许再加一个 `_machine.Suppressed = ...` 的赋值点。

## 2.4 单实例

Mutex `Global\HotkeyHud.SingleInstance`。第二实例直接退出，并弹一次气泡提示「已在运行，见系统托盘」。

## 2.5 不要做

- 不做安装器 / MSIX 打包（S6 或发布阶段）
- 不做自动更新
- 不做主题切换
- 不改 `Core` 任何规则、不改 `GameClassifier`
- 不改 §6.1 的其他视觉值
