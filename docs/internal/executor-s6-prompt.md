# 一、开工前置：S5 遗留（2 项）

## 1.1 `Local\` 改为首选，不是兜底

现状：`Global\HotkeyHud.SingleInstance` 优先，失败退 `Local\`。

**这是反的。** 本工具是**每用户每会话**的东西：配置在 `%APPDATA%`、Raw Input 只收本会话输入、托盘图标属于本用户。
两个用户同时登录（快速用户切换）时，**各自都应该有一份**，全局单实例反而是错的。

改成：直接用 `Local\`，删掉 `Global\` 分支。少一个分支，少一个权限失败路径。

## 1.2 配置越界改为钳制 + 提示

现状：值越界（如 `dwellMs=60000`）按"配置损坏"处理 → 整份改名 + 全用默认值。

**代价过大**：用户只错了一个字段，却丢掉 `knownShortcuts` 和 `extraGameProcesses`。

改成两条路径分开：

| 情况 | 处理 |
|---|---|
| JSON 语法错 / 字段类型错 / 无法解析 | 走损坏流程：改名 `config.broken.json` + 默认值 + 气泡 |
| **值越界**（`dwellMs` 不在 80–5000） | **钳制到边界 + 保留其它字段 + 气泡说明「dwellMs 超出范围，已改为 5000」** |

你原来的担心（"钳制会让用户以为改生效了"）成立，但**气泡提示**已经解决了它；而整份作废的代价更大。

# 二、S6 范围（只做 3 项）

## 2.1 混合 DPI（这是 bug，不是打磨）

**现状**：`HudApp.cs:289` 用 `Screen.PrimaryScreen.Bounds` 定位，`OverlayForm.cs:224` 用 `GetDpiForWindow(Handle)` 取缩放。
两个问题：

1. 定位永远按主屏算，光标在副屏时面板跑到主屏去
2. `GetDpiForWindow` 读的是**窗口当前所在屏**的 DPI，而定位前窗口还在旧位置 → 缩放取错

**要求**：

```
目标屏 = MonitorFromPoint(光标)
缩放   = 目标屏的 DPI / 96
尺寸与位置都按目标屏的工作区算
```

并开启 Per-Monitor V2（当前 csproj 与 `Program.cs` 都没有 DPI 声明，默认是 SystemAware，副屏会被系统虚拟化 → 糊）。

**验收**：100% + 150% 双屏，光标移到副屏后长按，面板出现在副屏、文字清晰、不裁切、不越界。**必须给截图。**

## 2.2 上缘翻转

规则：**光标在工作区上半部 → 面板贴下缘；光标在下半部 → 面板贴上缘。**

理由：视线跟着光标走，面板放在远离光标的一侧，遮挡最少。

**验收**：光标移到屏幕下方 → 面板在上缘；移到上方 → 回下缘；切换后 100ms 内完成。

## 2.3 淡入 120ms

- 用 `UpdateLayeredWindow` 的 `SourceConstantAlpha` 逐帧，16ms 一帧，ease-out
- **隐藏不做动画**，必须立即消失（这是"不打扰"的底线）
- 尊重系统「减少动画」设置（`SPI_GETCLIENTAREAANIMATION`），关闭时直接显示

**验收**：首帧 p95 仍 < 25ms（含动画首帧）；关闭系统动画后无淡入。

# 三、不做清单（越界即返工）

| 项 | 为什么不做 |
|---|---|
| Acrylic / 毛玻璃 | 需要 `SetWindowCompositionAttribute`，性能代价明显，且我们已定不透明。**做了会把 8ms 的首帧拖到 30ms+** |
| 键位热力图 | 这是 v2 的差异化功能，不是打磨。要做需要重做布局与数据映射 |
| 左右 Ctrl 区分 | 边缘需求，收益远小于复杂度 |
| 热键冲突检测 | 需要试探性 `RegisterHotKey`，有毫秒级竞态，且会短暂抢占用户热键 |
| 主题切换（明/暗） | 没人要求，面板本来就是深色 |
| 启动延迟（计划任务） | 复杂度高于收益，S5 的 HKCU Run 已够用 |
| 设置 UI 页面 | 配置只有 4 个字段，改 JSON 比做设置页快 |

**这七项如果做了，不算加分，算跑偏。**
