# 阶段闸门协议

每个阶段（S1、S2…）验收结束时，**无论通过与否**，都必须产出一份下一阶段的提示词文档。

## 1 三种结论对应三种提示词

| 验收结论 | 提示词内容 |
|---|---|
| 通过 | 下一阶段的任务、接口契约、验收用例、禁止事项 |
| 有条件通过 | 同上 **+ 本阶段遗留整改项，列为开工前置**（带 `文件:行号`） |
| 不通过 | **不写下一阶段**。写「返工提示词」：只含失败项、复现步骤、验收判定、不许动的部分 |

## 2 文件命名

```
docs/executor-s<N>-prompt.md
```

返工用 `docs/executor-s<N>-rework.md`，通过后并入下一阶段。

## 3 三条硬约束

1. **不得引入新需求**。提示词只能引用 `docs/shortcut-display-spec.md` 的章节，不能自己加功能。
2. **不得改规格原文**。发现缺口写 `[SPEC-GAP]`，给最小合理解释并标注，由人决定是否回写规格。
3. **必须包含「与既有规划的对应关系」一节**，逐条映射到规格章节号。映射不上的一律视为跑偏。

## 4 为什么要有这个协议

阶段之间最容易发生的不是做错，是**悄悄扩大范围**：
S2 顺手把 S3 的渲染写了，S3 又顺手把 S2 的阈值改了。等到验收时，没人说得清是谁在什么时候把范围挪了。

闸门协议的作用：每次交接都有书面契约，事后可追溯。
