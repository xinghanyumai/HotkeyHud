# 角色与本次任务

功能层面已冻结。本次做**发布准备**：让一个没见过这个项目的人能装上、用起来、卸干净。

**本阶段不写功能代码。** 唯一的代码改动是发布配置与图标资源。

---

# 一、开工前置：S6 遗留（2 项）

| # | 整改 | 判定 |
|---|---|---|
| 1 | 面板锚定改为「显示时定一次，仅跨屏才重锚」 | 同屏内移动光标，面板不上下跳 |
| 2 | README 的「六项门禁」改为「八项门禁」 | 与实际命令一致 |

第 1 项的原因：现在每 20ms 重锚一次，光标越过工作区中线时面板会从下缘跳到上缘。
用户按住 Ctrl 拖动鼠标时会看到面板来回跳——这是明显瑕疵。

保留「跨屏重锚」：光标移到另一块屏时应该跟过去，那是正确行为。

---

# 二、必须做（4 项）

## 2.1 发布形态（先决策，再打包）

| 方案 | 体积 | 用户要求 | 评价 |
|---|---|---|---|
| 框架依赖 | ~1 MB | 必须装 .NET 10 Desktop Runtime | ❌ 对轻量工具是致命门槛 |
| **自包含 + 单文件** | ~60–70 MB | 无 | ⚠️ 能跑但体积违和 |
| **自包含 + 裁剪** | ~25–35 MB | 无 | ✅ 首选，但 WinForms 裁剪有反射风险 |
| NativeAOT | ~10 MB | 无 | ❌ WinForms 支持不完整 |

**要求**：先做自包含 + 裁剪，跑完整八项门禁；任何一项失败就退回不裁剪的自包含，并在 README 记录体积与原因。

**验收**：在一台**没装 .NET** 的机器（或干净的 Windows 沙盒）上双击能启动。

## 2.2 面向用户的 README

现在的 README 是开发日志，用户看不懂。重写为：

```
它是什么（3 行）
怎么启动（含托盘图标可能被折叠到「隐藏的图标」）
怎么用（按住 Ctrl/Alt/Shift/Win）
怎么加自己的应用（Data/apps 的 JSON 格式 + 一个完整示例）
怎么配置（4 个字段 + 取值范围）
怎么卸载（退出 → 关自启 → 删目录 → 删 %APPDATA%\HotkeyHud）
已知限制（提权窗口不响应、独占全屏不显示、单屏未验证混合 DPI）
```

**保留**原有的开发文档（架构、决策、SPEC-GAP），移到 `docs/` 或 README 末尾的「开发」章节。

## 2.3 首次运行引导

第一次启动（配置文件不存在）时，托盘弹一次气泡：

```
HotkeyHud 已在托盘运行
按住 Ctrl 或 Alt 查看当前应用的快捷键
```

只弹一次。第二次启动不弹（用配置里的标记位，不要用"文件是否存在"——用户可能删了配置但用过）。

## 2.4 卸载可逆

| 项 | 清理方式 |
|---|---|
| 自启注册表 | 退出前若开启则提示「开机自启仍开启，退出后仍会启动」；README 写明手动关闭路径 |
| `%APPDATA%\HotkeyHud` | 不自动删（含用户自定义档案），README 说明位置 |
| 程序目录 | 用户手动删 |

**不做卸载器**，但必须让用户知道删什么。

# 三、建议做（3 项）

| 项 | 理由 |
|---|---|
| 应用图标 `.ico`（16/32/48/256） | 现在托盘是代码绘制的，exe 文件图标还是默认的。资源管理器里一眼认不出 |
| 版本号写入程序集 + 托盘 tooltip | `1.0.0`，方便用户报问题时说版本 |
| 崩溃日志位置写进 README | `%TEMP%\hotkeyhud-startup.log`，用户反馈时能直接给 |

---

# 四、可以不做（明确排除）

| 项 | 理由 |
|---|---|
| 安装器（MSI / Inno Setup） | 绿色版够用，安装器会引入卸载残留、权限、签名三重复杂度 |
| 自动更新 | 需要更新服务器 + 签名校验 + 回滚策略，v1 不需要 |
| 商店上架 | 审核周期与合规成本远超收益 |
| 多语言 | 中文用户为主，英文界面留 v2 |

---

# 五、验收（5 条）

| # | 项 | 判定 |
|---|---|---|
| 1 | 干净机器可运行 | 没装 .NET 的机器双击启动，托盘出现，按 Ctrl 出面板 |
| 2 | 体积 | 记录实际大小；若裁剪失败退回不裁剪，说明原因 |
| 3 | README 可操作 | 找一个没接触过项目的人，只读 README 能完成「启动 → 加一个自定义应用 → 卸载」 |
| 4 | 首次引导 | 首次启动弹一次气泡，第二次不弹 |
| 5 | 八项门禁 | 全部仍绿（发布配置不得改变行为） |

第 3 条是最容易被糊弄的：**自己读自己的 README 不算验证**，要么找真人，要么逐条照做并记录卡在哪。

---

# 六、禁止事项

1. 不加功能。任何"顺手做了个 XX"都算跑偏。
2. 不为减体积删诊断入口——`#if DEBUG` 已经把它们挡在 Release 外了。
3. 不改 `Core` 与数据档案。
4. 不在 README 里写「已验证」而实际没验证——S6 的副屏就是例子，写「未验证」。
5. 不把 `%APPDATA%` 或注册表操作做成"静默执行"，每一步都要在 README 里可查。

# 八、开工顺序

1. 先做第一节 2 项整改，跑八项门禁。
2. 再定发布形态，打一次包，在干净环境试跑。
3. 写 README，找人试读。
4. 最后补首次引导与图标（改动最小，放最后）。
5. 出包，交付。

**第 2 步必须在第 3 步之前**：如果裁剪把功能裁坏了，README 写得再好也没用。
