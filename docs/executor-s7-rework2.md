# 一、熟记名单：从「过滤」改为「降权」（规格 §4.3 v1.7）

## 1.1 行为变更

| 作用点 | 旧 | 新 |
|---|---|---|
| 列表 | 整条剔除 | **保留**，归入「通用」组，排在所有应用组之后（最后一页） |
| 闪烁 | 不进入 Flashing，直接收起 | **正常高亮 500ms** |
| 字段 | `HiddenByKnownCount` | `DeferredKnownCount` |

**理由**：直接放进首页会让 Word 的 38 条里前 6 条全是 Ctrl+C/V/X/Z/A/S，把应用特有的挤到第二页——那是另一个方向的缺功能。放最后一页两头都满足。

## 1.2 配置语义不变

- `knownShortcuts: null` → 用内置名单
- `knownShortcuts: []` → 名单为空，全部按普通条目排序
- 名单里的组合**不再被剔除**，只是被归到「通用」组

## 1.3 验收

Word 的 Ctrl 面板翻到最后一页，能看到「通用」组，含 `Ctrl+C` `Ctrl+V` `Ctrl+Z` `Ctrl+A` `Ctrl+S`；按下 Ctrl+C 时该条**高亮 500ms 后收起**，不是立即消失。

# 二、排序改「组优先」（规格 §3.2 v1.7）

```
先按档案里的组顺序
组内按修饰键数量升序（Ctrl+S 在 Ctrl+Shift+S 之前）
「通用」组固定排最后
```

v1.5 的「全局按修饰键数排序」会把同一组打散——Word 第 1 页出现 5 个组名（插入 / 字体 / 字体（续）/ 段落 / 段落（续））就是这个原因。

**验收**：Word 第 1 页组名 ≤ 3 个；同一组的条目连续出现。

# 三、用 Computer Use 抄录 4 个应用（用户已授权）

微信 / QQ / 网易云音乐 / 豆包 **没有官方快捷键文档**，只能从应用内 `设置 → 快捷键` 抄。

## 3.1 流程（每个应用重复）

1. 用 Computer Use 打开该应用
2. 进入 `设置` → 找 `快捷键` / `热键` / `键盘`
3. **截整屏**，存 `docs/evidence/<app>-shortcuts.png`
4. 照截图逐条抄进 `Data/apps/<app>.json`
5. **抄完回头对一遍截图**，确认没有漏行、没有看错键位
6. 在 README 核对表写：应用 / 来源=`应用内设置页` / 核对日期 / 条数 / 截图路径

## 3.2 抄录规则

| 规则 | 说明 |
|---|---|
| 只收「修饰键 + 键」的组合 | 单键（如 `F5` 刷新）不符合触发模型，跳过 |
| 键位照抄，不改写 | 应用写 `Ctrl+Shift+Z`，就写 `Ctrl+Shift+Z` |
| 动作文案 ≤ 6 汉字 | 超长的压缩，别截断成省略号 |
| 拿不到就写「未收录」 | 需要登录、版本不同、找不到设置页 → **不填**，在 README 记原因 |
| 禁止凭印象补 | 截图里没有的，一条都不许加 |

## 3.3 进程名怎么确认

抄之前先在任务管理器确认进程名（如微信可能是 `WeChat.exe`，QQ 可能是 `QQ.exe`，网易云可能是 `cloudmusic.exe`，豆包可能是 `Doubao.exe`）。
**进程名错 = 整个档案不生效**，这是最容易犯的错。

# 四、Word 的下一步

你在开发机复现不出来，判断是对的。按这个顺序收尾：

1. **先用新构建再试一次**。用户之前跑的是 11-17 启动的旧实例（exe 构建于 11-12），本轮改了 `HudApp` 与 `HudBuilder`，旧实例不含这些改动。
2. 仍然没有 → 让用户带 `--diag` 复现，取最后 3 行。
3. 重点看 `fg` 行的 `uipiBlocked`：
   - `true` → Word 以管理员启动，UIPI 阻断，**不是代码问题**，写进已知限制
   - `false` 且没有 `mod` 行 → Raw Input 没收到，回到输入层查
   - 有 `show` 行但 `overlayRect` 异常 → 定位问题

**不要在没有新日志的情况下再改判定逻辑。**
