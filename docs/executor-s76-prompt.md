# 零、根因（已定位，不要重新猜）

## Bug 1：钩子对 keydown 与 keyup 各触发一次

`Platform/LowLevelKeyboardHook.cs` 的 `OnKeyboard`：

```csharp
int virtualKey = Marshal.ReadInt32(lParam);   // 只读了 vkCode（偏移 0）
if (_shouldSwallow(virtualKey))
{
    _onSwallow?.Invoke(virtualKey);           // ← 按下、松开各调一次
    return 1;
}
```

`KBDLLHOOKSTRUCT` 的布局：

| 偏移 | 字段 |
|---|---|
| 0 | `vkCode` |
| 4 | `scanCode` |
| **8** | **`flags`（`LLKHF_UP = 0x80`）** |
| 12 | `time` |

钩子对按下和松开都会回调，代码没看 `flags`，所以两次都执行了 `_onSwallow` → 翻两页。

**修法**：
- `return 1` 两种情况都要（松开也必须吞，否则前台应用收到孤立 keyup）
- `_onSwallow` **只在 `(flags & 0x80) == 0`（按下）时调用**

## Bug 2：翻页时重新测量尺寸，导致位置跳

`OverlayForm.ShowModel` 每次都走 `ResolveBounds(model)` → `HudPanel.Measure(model, ...)`。
`Measure` 按**当前页的条目数**算高度。末页条目少 → 高度变小 → 底部锚定的面板顶边下移 → 视觉上「面板跳了一下」。

`OnPageRequested` → `BuildAndRender` → `ShowModel`，所以每翻一页都重算一次。

**修法**：
1. `Measure` 改用**跨页恒定的格数预算**（`HudModel.CellBudget` 或该修饰键下最大页的格数），与当前页内容无关
2. 翻页时**不重算 bounds**：复用上一次的 bounds，只重绘内容
3. 只有「首次显示」与「跨屏」才重算 bounds

**验收**：连翻 3 页，`GetWindowRect` 四次完全一致。

# 二、Part B：设置页

## 2.1 形态（轻量优先）

| 项 | 决定 |
|---|---|
| 技术 | WinForms 单窗体，**手写布局，不用 Designer** |
| 尺寸 | 约 780×560，可缩放（最小 640×420） |
| 模态 | 非模态，关闭即 `Dispose`，不常驻 |
| 内存 | 打开时 ≤ 8 MB 增量，关闭后回落 |
| 依赖 | 零新增 NuGet |

**不许用 WebView / 浏览器内核**——那会把 12 MB 的常驻进程变成 80 MB。

## 2.2 布局

```
┌──────────────────────────────────────────────────┐
│ 应用                 │ 快捷键                    │
│ ┌─────────────────┐  │ ┌──────────────────────┐ │
│ │ Word        26  │  │ │ 键位     动作    颜色 │ │
│ │ Chrome      21  │  │ │ Ctrl+K  插入链接  ●  │ │
│ │ VS Code     27  │  │ │ ...                   │ │
│ │ ─────────────── │  │ └──────────────────────┘ │
│ │ 我的应用    +   │  │ [+ 添加] [删除]           │
│ └─────────────────┘  │                           │
│ [添加应用…]           │                           │
├──────────────────────────────────────────────────┤
│ 改完点保存，托盘会自动重载          [保存] [关闭] │
└──────────────────────────────────────────────────┘
```

## 2.3 三条关键交互

**① 内置档案只读，编辑时自动另存为用户覆盖**

用户想改 Word 的条目，**不许改安装目录里的 `winword.json`**。
点「编辑」时把内置档案复制到 `%APPDATA%\HotkeyHud\apps\winword.json`，之后所有修改写用户副本。

列表里用不同颜色/图标区分「内置（只读）」与「我的（可改）」。

**② 加条目时直接按组合键录入**

点「+ 添加」→ 新行进入编辑态 → **用户直接按下 `Ctrl+Alt+F`，自动填入**。
比让用户手打字符串快得多，也不会打错格式。

实现：编辑态捕获 `KeyDown`，取 `ModifierKeys` + `KeyCode` 拼成 `Ctrl+Alt+F`。`Esc` 取消。

**③ 颜色只给预设，不做自由取色**

8 个预设色（含「默认」）。自由取色会做出看不清的组合，而面板是深底。

选中后该条目的**键帽描边与文字**用该色；不选则用修饰键默认色。

## 2.4 明确不做

| 项 | 为什么 |
|---|---|
| **执行动作**（按下快捷键真的启动程序/跑命令） | 这是宏工具，不是提示工具。执行任意命令有安全风险，且需要确认流程与签名 |
| 自由取色器 | 会做出低对比配色 |
| 导入/导出配置包 | 用户可自己复制 JSON |
| 拖拽排序 | 排序由分组决定，拖拽会破坏组结构 |

> 「绑定特定快捷键操作」本期实现为**填写动作描述**，不实现为执行。若你要的是执行，需要单独一轮设计（涉及安全确认、白名单、失败提示）。

## 2.5 数据

`ShortcutEntry` 增加可选字段：

```jsonc
{ "keys": "Ctrl+Alt+F", "action": "格式化文档", "group": "编辑", "color": "#4C8DFF" }
```

- `color` 缺省 = 用修饰键默认色
- 只接受 8 个预设值之一，其他值按缺省处理并记警告
- 用户档案里可写；内置档案不写
